El código ofrece controles separados para borrar CV, foto y alertas de empleo. El endpoint de exportación admin cubre el conjunto de datos. No hay una pantalla única para exportar o borrar todos los datos de una persona. La desactivación de una cuenta bloquea su uso y no equivale a borrar sus datos.

## Retención y exportación

Biovity aprobó conservar datos de candidatos durante 24 meses desde el cierre del caso y luego borrarlos o anonimizarlos. La Ley 21.719, artículo 3(c), limita la conservación al tiempo necesario para el propósito, salvo una excepción legal. La ley entra en vigor el 2026-12-01. El plazo de 24 meses es una política de Biovity. No es un plazo fijado por la ley. Revisa la política con asesoría legal antes de publicarla.

El backend considera cerrado un caso cuando una postulación tiene estado `contratado`, `rechazado` o `desistido`. Usa la última transición terminal del historial como fecha de cierre. Una reapertura cambia el estado y detiene el vencimiento. Si la postulación no tiene historial, el backend usa `updatedAt`, que puede extender el plazo.

El backend vence los datos de un candidato cuando todas sus postulaciones están cerradas y la más reciente tiene al menos 24 meses. El proceso incluye cuentas activas e inactivas. Borra las postulaciones y sus datos ATS relacionados. También borra los eventos de entrevista, participantes y RSVP, chats, alertas de empleo, búsquedas guardadas de empleo, etiquetas asignadas, avisos, sesiones y credenciales. El proceso agrega los CV, cargas incompletas, adjuntos de mensajes y PDFs de ofertas de Supabase Storage a `resume_cv_cleanup` dentro de la misma transacción. Cada tarea incluye el bucket y la ruta del objeto. El worker recibe esos campos y borra el objeto cuando ninguna fila lo referencia.

El backend mantiene la fila `user` con correo, nombre y profesión sustituidos por valores anónimos. Otras tablas tienen claves foráneas que requieren ese identificador. La tabla `candidate_data_lifecycle_audit` conserva el identificador interno, la fecha, el actor cuando aplica y el conteo de registros. No guarda campos del perfil ni contenido ATS. El endpoint admin `GET /api/v1/admin/candidate-data/:candidateId/export` exporta el perfil, currículum, snapshots históricos de perfil, postulaciones, evaluaciones, notas, historial, eventos, participantes, RSVP, scorecards y decisiones de entrevista, ofertas, puntajes de IA, alertas, trabajos guardados, chats, mensajes y referencias de archivos. Registra cada exportación.

La cola `resume_cv_cleanup` entrega `bucket` y `path` al worker de almacenamiento. El worker de despliegue debe usar el bucket de cada tarea. Las rutas pendientes permanecen en la cola hasta que el worker las borre. Una ruta protegida por otra referencia también permanece para proteger ese archivo.

Las migraciones `candidate_data_retention_lifecycle` y `restrict_candidate_lifecycle_audit_grants` están aplicadas en Supabase. Una prueba SQL confirmó el trigger para cuentas inactivas y revirtió todas las filas de prueba. Una prueba SQL local con dos conexiones comprobó la secuencia de bloqueo y lectura después de anonimizar en un esquema aislado. La prueba usó una base PostgreSQL temporal y la eliminó al terminar. No ejecutó el repositorio TypeORM completo.

El worker de correo borra mensajes `sent`, `dead` o `suppressed` cuando vence `expires_at`. También borra sus registros de reintento admin. La limpieza corre aunque falte `RESEND_API_KEY`. Este cambio aún no está desplegado.

El flujo no define la base legal ni los plazos de retención de datos en proveedores de correo, registros de acceso, copias de seguridad, proveedores de IA ni calendarios externos. Biovity debe definir estas reglas con asesoría legal. No declarar completa la eliminación en todos los servicios externos hasta configurar y comprobar sus plazos.
